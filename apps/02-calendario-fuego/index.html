Modelo de negocio

Seguros, bomberos y municipios

  • Problema: los focos se publican cada 10 minutos, pero no se convierten en prioridad operativa.
  • Usuario: defensa civil, bomberos voluntarios, aseguradoras agropecuarias.
  • Ingreso: suscripción por provincia + API para integrar en sistemas de emergencia.
  • Valor: prioriza por FRP y proximidad a población/infraestructura, no solo por conteo.
Solución probable

Armonizar antes de comparar

Normalizar satélites y horarios (MODIS, VIIRS, GOES) para evitar doble conteo.

Calcular anomalía diaria/semanal y marcar picos contra la climatología.

Cruzar con viento, humedad y cobertura vegetal para estimar propagación.

Esta demo resuelve el filtrado y la anomalía; la propagación queda como siguiente etapa.

Qué más se puede pedir

  • FRP y confianza: los CSV traen frp y risco_fogo; se pueden calibrar umbrales.
  • Área quemada: GeoTIFF/SHP de INPE para medir hectáreas, no solo puntos.
  • Viento y humedad: POWER u Open-Meteo para estimar propagación.
  • Población e infraestructura: capas OSM/IGN para priorizar impacto.
  • GOES: focos cada 10 min para detección temprana.

Alcance y reglas

Licencia: datos abiertos INPE; atribución. FIRMS requiere clave gratuita y sus términos. GOES/CONAE tiene atribución.

Cuidado: un foco es una detección, no un incendio confirmado. No usar para acusaciones ni para promoción comercial.

Límite: la anomalía es contra el promedio del período cargado, no contra una climatología de 20 años.

Cómo mejorar para otros servicios

Construir una climatología por provincia con 10-20 años de FIRMS/INPE.

Deduplicar focos entre satélites con ventana espacial y temporal.

Integrar un modelo de propagación y alertas push por WhatsApp/SMS.

Exponer una API de priorización para bomberos y municipios.
